# Промпт для ИИ-разработчика: веб-приложение «Статус форумы»

> Как использовать: положите в папку `/seed` репозитория файл мастер-плана (Excel) и PDF с черновиком диаграмм, откройте репозиторий в ИИ-агенте для разработки (Claude Code, Cursor и т. п.) и вставьте текст ниже целиком. Vercel подключается к репозиторию уже после того, как агент напишет код (см. раздел «Деплой»).

---

## Роль и задача

Ты — senior full-stack разработчик. Создай с нуля production-ready веб-приложение **«Статус форумы»** для планирования и контроля подготовки деловых форумов. Код хранится в репозитории GitHub, деплой — на **Vercel** (автодеплой из ветки `main`, preview-деплой для каждого Pull Request).

**Главное ограничение: у владельца нет платных аккаунтов ни в одном сервисе.** Всё должно работать на бесплатных тарифах: GitHub Free, Vercel Hobby, Neon Free. Никаких платных API, платных библиотек и сервисов, требующих банковскую карту. Собственного домена нет — сайт работает на адресе `*.vercel.app`. Vercel к репозиторию ещё не подключён, поэтому код сначала должен собираться и запускаться локально, а в README нужна пошаговая инструкция первого подключения.

Работай поэтапно (см. раздел «План работ»). После каждого этапа делай коммит с понятным сообщением. Интерфейс, тексты, форматы дат (ДД.ММ.ГГГГ) и чисел (1 234,56) — на русском. Часовой пояс — Europe/Moscow.

## Технологический стек

- **Next.js 15 (App Router) + TypeScript** (strict).
- **Tailwind CSS + shadcn/ui**: таблицы, модальные окна, выпадающие списки, календари.
- **База данных:** Postgres на **бесплатном тарифе Neon** (подключается из панели Vercel → Storage, карта не нужна), ORM — **Prisma**. Миграции и seed-скрипт. Для локальной разработки — тот же Neon (отдельная ветка БД) или локальный Postgres в Docker.
- **Excel импорт/экспорт:** `exceljs`.
- **Диаграммы отчёта:** `recharts`, кольцевые (donut) диаграммы.
- **Экспорт презентации:** `pptxgenjs` (PPTX с нативными, редактируемыми диаграммами PowerPoint) и `jspdf` (PDF, альбомная ориентация 16:9).
- **Диаграмма Ганта:** собственный компонент на React + SVG/CSS (без устаревших библиотек), см. требования ниже.
- **Напоминания:** Vercel Cron (на бесплатном тарифе — 1 запуск в сутки), уведомления внутри приложения и e-mail через **обычный почтовый ящик по SMTP** (`nodemailer`, например Яндекс Почта или Mail.ru с паролем приложения — бесплатно, без своего домена). Платные почтовые сервисы не использовать.
- **Валидация:** `zod`. Серверная логика — Server Actions / Route Handlers.

## Доступ и безопасность

1. Весь сайт закрыт паролем. Без авторизации доступна только страница `/login`.
2. Пароль хранится **только** в переменной окружения `APP_PASSWORD_HASH` (bcrypt-хеш), в коде его нет. Добавь скрипт `npm run hash-password`, который генерирует хеш.
3. После входа выдаётся подписанная httpOnly, Secure, SameSite=Lax cookie-сессия (`iron-session`, секрет в `SESSION_SECRET`) сроком 30 дней. Проверка — в `middleware.ts`.
4. Ограничение попыток входа: не больше 5 в минуту с одного IP. Есть кнопка «Выйти».
5. **HTTPS / SSL:** сайт работает только по HTTPS. Адрес `*.vercel.app` уже имеет SSL-сертификат бесплатно, ничего настраивать не нужно. Добавь заголовки безопасности: HSTS, X-Frame-Options, Content-Security-Policy, Referrer-Policy.
6. Архитектура должна позволять позже перейти на персональные логины (таблица `User` с ролями «Администратор / Редактор / Просмотр»). В MVP достаточно общего пароля.

## Визуальный стиль

- Деловой, строгий, минималистичный интерфейс. Основные цвета — **синий, чёрный, белый**:
  - основной синий `#1F4E9E` (кнопки, активные вкладки, ссылки), тёмно-синий `#0F2A5C` (шапка);
  - чёрный `#111111` (текст), белый `#FFFFFF` (фон), серые `#F4F6FA` / `#E3E7EF` (фон таблиц, разделители).
- Статусные цвета используются только для статусов: зелёный `#1E9E5A`, красный `#D93838`, серый `#8A94A6`.
- Шрифт Inter (или системный sans-serif). Скругления небольшие (6 px), тени минимальные.
- В шапке — название **«Статус форумы»**, хлебные крошки (Форумы → Название форума → Раздел) и кнопка «Выйти».
- Адаптивная вёрстка: на ноутбуке всё работает полноценно, на телефоне доступны просмотр, изменение статуса и поиск.

## Структура приложения (навигация)

```
/login                              — ввод пароля
/                                   — главная: плашки форумов + кнопка «База данных»
/database                           — справочники (сотрудники и прочие)
/forums/[id]/gantt                  — Диаграмма Ганта
/forums/[id]/tasks                  — Список этапов с задачами
/forums/[id]/report                 — Отчёт
```

### 1. Главная страница (сразу после ввода пароля)

- Сетка **плашек (карточек) форумов**. На каждой плашке:
  - название форума и дата проведения (обязательные поля);
  - прогресс-бар выполнения (% задач со статусом «Выполнено»);
  - счётчики «Не начато / В работе / Выполнено / Просрочено» (просроченные — красным);
  - сколько дней осталось до форума.
- Клик по плашке открывает форум (по умолчанию вкладка «Диаграмма Ганта»).
- Кнопка **«+ Новый форум»**. Форма: название, дата начала, дата окончания (необязательно, для многодневных форумов), дата старта продаж (по умолчанию дата форума − 4 месяца), место проведения (необязательно). Источник плана на выбор:
  - пустой план;
  - копия типового мастер-плана (из справочника задач);
  - копия плана другого форума;
  - загрузка из Excel.
- Меню плашки: редактировать, дублировать, архивировать, удалить (с подтверждением). Фильтр «Активные / Архив», сортировка по дате форума.
- Отдельная заметная кнопка **«База данных»** — переход в `/database`.

### 2. Раздел «База данных» (справочники)

Вкладки со справочниками, в каждом — добавление, редактирование, удаление (запрещено, если значение используется; в этом случае предлагается архивировать), поиск и сортировка:

1. **Ответственные (сотрудники команды):** ФИО, должность, роль/отдел (одна или несколько ролей из справочника ролей), e-mail, телефон, Telegram, признак «активен». Из этого справочника выбираются ответственные за задачи во всех форумах, а на e-mail отправляются напоминания.
2. **Этапы:** название, порядковый номер, цвет на диаграмме Ганта. Начальные значения: «1. Предстартовая подготовка», «2. Продажи и орг. подготовка», «3. Проведение и координация», «4. Завершение и пост-мероприятие».
3. **Блоки / направления:** название, порядок. Начальные значения — все уникальные блоки из мастер-плана (Концепция и стратегия, Финансы и бюджет, Площадка, Партнерства, Продажи, Маркетинг, Команда и т. д.).
4. **Роли:** Ивент, Отдел продаж, Маркетинг, Программа, Финансы, Юрист, Дизайн, Веб-разработчик, Команда проекта, Техническое обеспечение, Подрядчик по регистрации, «Вся команда», «Каждый по своему направлению».
5. **Задачи (типовой мастер-план):** шаблон задач с этапом, блоком, описанием, текстом срока и ролями. Используется при создании нового форума.
6. **Форумы (названия):** список форумов с датами (та же сущность, что на главной).

При импорте Excel новые значения этапов, блоков и ролей автоматически добавляются в справочники (после подтверждения в окне предпросмотра).

### 3. Форум: вкладки «Диаграмма Ганта», «Этапы и задачи», «Отчёт»

Над вкладками — название и дата форума, счётчики статусов (кликабельные: клик фильтрует задачи по этому статусу), кнопки «Загрузить план», «Выгрузить план».

#### Общая панель фильтров (одна и та же на вкладках Ганта и списка, состояние хранится в URL)

- Фильтры с множественным выбором: **Этап, Блок, Роль, Ответственный, Статус**.
- Фильтр **Срок**: диапазон дат, быстрые кнопки «Просрочено», «На этой неделе», «В ближайшие 14 дней», «Без даты».
- **Поиск по задачам** (по описанию и комментарию, без учёта регистра, с подсветкой найденного текста).
- Сортировка по любому столбцу: №, этап, блок, срок, роль, ответственный, статус. Кнопка «Сбросить фильтры».

## Модель данных задачи и статусы

Поля задачи: №, этап, блок, описание задачи, **исходный текст срока** (как в Excel), дата начала, дата окончания (срок), роли (одна или несколько), ответственные (один или несколько сотрудников из справочника), статус, дата фактического выполнения (ставится автоматически при переводе в «Выполнено»), комментарий, порядок сортировки, история изменений (кто/когда/что изменил: поле, было → стало).

**Статусы (хранятся 3 значения):**

| Статус | Отображение |
|---|---|
| Не начато | серый бейдж |
| В работе | **зелёный**, если сегодня ≤ срока; **красный**, если срок прошёл |
| Выполнено | синий бейдж с галочкой; если выполнено позже срока, рядом пометка «с опозданием N дн.» |

**Подсветка отставания:** у любой невыполненной задачи с прошедшим сроком строка подсвечивается светло-красным, а в отдельном столбце «Отставание» показано «+N дн.». Для задач «Не начато», у которых наступила дата начала, выводится предупреждающая иконка «пора начинать».

## Вкладка «Диаграмма Ганта»

- Слева — дерево: Этап → Блок → Задача (этапы и блоки сворачиваются). Справа — временная шкала.
- Масштаб: дни / недели / месяцы. Кнопка «К сегодняшнему дню».
- Вертикальные линии: «Сегодня» (синяя пунктирная), «Старт продаж», «Дата форума» (чёрная жирная).
- Цвет полосы задачи зависит от статуса и соблюдения сроков: серый — не начато, зелёный — в работе в срок, красный — в работе с просрочкой или не выполнено после срока, синий — выполнено. Сводные полосы этапов и блоков показывают прогресс.
- Задачи без вычисленной даты выводятся ромбиком на дату окончания этапа с жёлтой пометкой «уточнить срок».
- Перетаскиванием полосы меняются даты (сдвиг и изменение длины), изменения сохраняются в БД с отменой (Ctrl+Z / кнопка «Отменить»).
- При наведении — всплывающая подсказка: описание, даты, ответственные, статус, отставание. По клику — боковая панель редактирования задачи.
- Фильтры и поиск применяются и к диаграмме.

## Вкладка «Этапы и задачи»

- Таблица, сгруппированная по этапам (заголовок этапа сворачивается и показывает прогресс). Столбцы: №, Блок, Задача, Срок (текст), Дата начала, Дата окончания, Роль, Ответственный, Статус, Отставание, Комментарий.
- **Редактирование прямо в таблице:** статус — выпадающий список, ответственный — выбор из справочника сотрудников с поиском (можно несколько), даты — календарь, текст — по двойному клику. Сохранение автоматическое, с уведомлением «Сохранено».
- Добавление, удаление, дублирование задачи; изменение порядка перетаскиванием; массовые действия над выбранными строками (сменить статус, ответственного, сдвинуть сроки на N дней).
- Отдельный переключатель вида **«По статусам»**: три колонки-канбана «Не начато / В работе / Выполнено», карточки можно перетаскивать между колонками.

## Загрузка плана (импорт из Excel)

- Формат — как в прилагаемом файле `/seed/master-plan.xlsx`, лист «Мастер-план форума», столбцы:
  `№ | Этап | Блок / направление | Описание задачи | Срок готовности (относительно даты форума) | Ответственный блок / роль | Статус | Комментарий / примечание`.
- Дополнительные столбцы необязательны, но распознаются: `Ответственный (ФИО)`, `Дата начала`, `Дата окончания`.
- Окно **предпросмотра** перед сохранением: сколько строк будет добавлено или обновлено, новые значения справочников, строки с ошибками или нераспознанным сроком (подсвечены жёлтым). Режимы: «Заменить план» или «Добавить к плану».
- Роли вида «Ивент / Маркетинг», «Отдел продаж/Маркетинг» разбиваются по `/` на отдельные роли (с обрезкой пробелов).
- Нормализация: лишние пробелы («за 6 недель  до форума»), разный регистр.

### Правила перевода текстового срока в даты

Опорные даты: `F` — дата начала форума, `FE` — дата окончания (если не задана, равна `F`), `S` — дата старта продаж форума.

| Текст срока | Дата окончания | Дата начала |
|---|---|---|
| «за N дней / недель / месяцев до форума» | F − N дней/недель/месяцев | окончание − 7 дней |
| «за N–M недель до форума» (диапазон) | F − N недель (меньшее) | F − M недель (большее) |
| «за 1 день до форума, к 18:00» и прочие уточнения после запятой | по числу, уточнение → в комментарий | окончание − 1 день |
| «контрольная точка, за 4 месяца» | F − 4 месяца (веха) | = окончанию |
| «до старта продаж» | S | начало этапа 1 (S − 60 дней) |
| «с начала продаж», «с начала продаж, далее на регулярной основе» | F − 1 день | S |
| «в дни форума», «в день монтажа» | FE (монтаж: F − 1) | F (монтаж: F − 1) |
| «на следующий день после форума» | FE + 1 | FE + 1 |
| «в течение N дней после форума» | FE + N | FE + 1 |
| «в течение N рабочих дней после форума» | FE + N рабочих дней | FE + 1 |
| «на протяжении этапа…», «по графику платежей договоров», «при выборе площадки» и др. нераспознанное | границы этапа | границы этапа, флаг «уточнить срок» |

Границы этапов по умолчанию: этап 1 — от S − 60 дней до S; этап 2 — от S до F − 1; этап 3 — от F до FE; этап 4 — от FE + 1 до FE + 30. Парсер — отдельная функция с unit-тестами на **все** варианты срока из мастер-плана. Если у форума меняется дата, приложение предлагает пересчитать даты задач, у которых даты не редактировались вручную.

## Выгрузка плана (экспорт)

- Кнопка «Выгрузить план» → `.xlsx` в том же формате, что и при импорте, плюс столбцы «Ответственный (ФИО)», «Дата начала», «Дата окончания», «Отставание, дн.». Учитываются текущие фильтры (выбор: «всё» / «только отфильтрованное»).
- Оформление файла: закреплённая шапка, автофильтр, ширина столбцов, заливка по статусу.
- Файл, выгруженный из системы, загружается обратно без потерь данных.

## Напоминания по статусам

- Ежедневный запуск через **Vercel Cron** утром (`0 6 * * *` UTC = 09:00 МСК; на бесплатном тарифе Vercel может запустить задачу в любой момент в пределах этого часа — это нормально). Эндпоинт `/api/cron/reminders` защищён `CRON_SECRET`. Не больше одного cron-задания в день, чтобы уложиться в лимиты Hobby.
- Каждому ответственному уходит одно письмо-дайджест (через SMTP обычного почтового ящика) со списком его задач по всем активным форумам. Учитывай суточный лимит бесплатной почты: письма одному адресату объединяются, общее число писем за запуск ограничено настройкой (по умолчанию 50). Если SMTP не настроен, напоминания работают только внутри сайта, без ошибок сборки.
  - срок наступает через N дней (N настраивается, по умолчанию 3) и задача не выполнена;
  - задача просрочена (статус «Не начато» или «В работе»);
  - наступила дата начала, а статус по-прежнему «Не начато».
- Раз в неделю (понедельник) руководителю (e-mail в настройках) уходит сводка по каждому форуму: сколько задач выполнено, в работе и просрочено, топ-10 просрочек.
- В шапке сайта — колокольчик с теми же уведомлениями.
- Страница «Настройки напоминаний»: включение/выключение, N дней, получатели сводки. Все отправки записываются в журнал, повторные письма об одной задаче в тот же день не отправляются.

## Вкладка «Отчёт» (у каждого форума своя)

Образец — PDF-черновик в `/seed` (форумы «СтройТех’26», «СнабТех’26»). Цвета берутся из этого ТЗ, а не из черновика.

### Содержимое

1. Поле **«Дата составления отчёта»** (календарь, по умолчанию — сегодня); выводится в шапке отчёта и в экспорте.
2. Три красивые **кольцевые диаграммы** (donut):
   - **«Расходы»** — оттенки **красного** (от `#7F1D1D` до `#FCA5A5`);
   - **«Доходы»** — оттенки **зелёного** (от `#14532D` до `#86EFAC`);
   - **«Кто пригласил»** — оттенки **синего** (от `#0F2A5C` до `#93C5FD`).
   В центре кольца — итоговая сумма крупно («14,69» и подпись «млн руб.»). Подписи сегментов — «Название; сумма» с выносками и процентом; легенда справа; сегменты отсортированы по убыванию; плавная анимация и всплывающая подсказка при наведении. Подписи не должны перекрываться: мелкие сегменты (< 3 %) выносятся линиями.
3. Под каждой диаграммой — таблица данных (название, сумма, доля %) с итогом.

### Редактирование на сайте (справочники отчёта)

- **Диаграммы:** добавить, переименовать или удалить диаграмму, выбрать цветовую гамму (красная / зелёная / синяя), задать **порядок следования** (перетаскиванием), единицу измерения (по умолчанию «млн руб.»). По умолчанию у форума создаются три диаграммы: «Расходы», «Доходы», «Кто пригласил».
- **Состав данных каждой диаграммы:** строки «название + сумма» (сумма — десятичное число, ввод с запятой), добавление, удаление, изменение порядка. Итог считается автоматически.
- Кнопка «Скопировать структуру отчёта из другого форума» (названия и строки без сумм или вместе с суммами).

### Выгрузка отчёта в одну презентацию

- Кнопки **«Скачать PPTX»** и **«Скачать PDF»**. В файле: титульный слайд (название форума, дата форума, дата составления отчёта) и по одному слайду на каждую диаграмму в заданном порядке. Слайды 16:9 в фирменном стиле: белый фон, синяя плашка заголовка, номер страницы.
- В PPTX диаграммы вставляются **нативными doughnut-диаграммами PowerPoint** (редактируемыми), с теми же цветами и подписями.
- В PDF — векторная или высококачественная (2x) отрисовка тех же диаграмм.

## Нефункциональные требования

- Скорость: список из 500 задач фильтруется без задержек (фильтрация на клиенте, мемоизация).
- Все формы валидируются (zod) и на клиенте, и на сервере; понятные сообщения об ошибках на русском.
- Удаление требует подтверждения; форумы архивируются (мягкое удаление).
- Тесты: unit-тесты (Vitest) для парсера сроков, расчёта статусного цвета и отставания, импорта/экспорта Excel; один e2e-сценарий (Playwright): вход → создание форума → импорт Excel → смена статуса → экспорт PPTX.
- Качество кода: ESLint + Prettier, без `any`, серверные операции только для авторизованной сессии.
- `README.md` на русском: локальный запуск, переменные окружения, деплой, как сменить пароль, как делать резервную копию БД.

## Переменные окружения (`.env.example`)

```
DATABASE_URL=            # Neon Postgres (подставляется Vercel автоматически)
APP_PASSWORD_HASH=       # bcrypt-хеш пароля входа
SESSION_SECRET=          # случайная строка ≥ 32 символов
CRON_SECRET=             # секрет для /api/cron/*
SMTP_HOST=               # необязательно, напр. smtp.yandex.ru
SMTP_PORT=               # 465
SMTP_USER=               # адрес почтового ящика
SMTP_PASSWORD=           # пароль приложения (не основной пароль от почты)
APP_URL=                 # https://<имя-проекта>.vercel.app — для ссылок в письмах
```

Все ключи генерируются бесплатно. Для секретов добавь скрипт `npm run gen-secrets`, который выводит готовые значения `SESSION_SECRET`, `CRON_SECRET` и хеш пароля.

## Деплой — первое подключение Vercel (опиши в README пошагово, простым языком, для человека без опыта)

1. Зайти на vercel.com → **Sign Up** → **Continue with GitHub**. Выбрать бесплатный тариф **Hobby**. Банковская карта не нужна.
2. **Add New… → Project** → найти свой репозиторий в списке → **Import**. Если репозитория нет в списке — нажать «Adjust GitHub App Permissions» и дать Vercel доступ к нему.
3. Framework определится как Next.js автоматически. Первую сборку можно запускать сразу, даже если она упадёт из-за отсутствия БД.
4. В проекте Vercel → вкладка **Storage** → **Create Database** → **Neon** (Postgres) → тариф **Free** → Connect to project. Переменная `DATABASE_URL` добавится сама.
5. **Settings → Environment Variables**: добавить `APP_PASSWORD_HASH`, `SESSION_SECRET`, `CRON_SECRET`, `APP_URL` (и SMTP-переменные, если нужны письма). Значения получить командой `npm run gen-secrets`.
6. **Deployments → Redeploy**. Build Command в `package.json`: `prisma migrate deploy && next build` — таблицы создаются автоматически.
7. Загрузить стартовые данные один раз: `npm run db:seed` локально с `DATABASE_URL` из Vercel (или через защищённый эндпоинт `/api/admin/seed`, доступный только после входа, с кнопкой в «Базе данных»).
8. Открыть `https://<имя-проекта>.vercel.app`, ввести пароль. Дальше каждый push в `main` обновляет сайт автоматически.
9. `vercel.json` с одним cron-заданием на день.

## Ограничения бесплатных тарифов (учти в архитектуре)

- **Vercel Hobby:** 1 cron-задание в сутки; время выполнения функции ограничено — импорт Excel и экспорт PPTX/PDF делать на клиенте (в браузере), а не на сервере. Файлы не хранить на Vercel: всё в БД.
- **Neon Free:** БД «засыпает» при простое, первый запрос после паузы идёт на несколько секунд дольше — показывать индикатор загрузки. Хранилище небольшое (сотни МБ) — этого с запасом хватает для текстовых данных; не хранить в БД картинки и файлы.
- Не подключать платные сервисы мониторинга, аналитики, почты и хранилищ.
