# Статус форумы

Веб-приложение для планирования и контроля подготовки деловых форумов: план задач по этапам, диаграмма Ганта,
статусы и отставания, напоминания ответственным, отчёт с кольцевыми диаграммами и выгрузкой в PowerPoint и PDF.

Всё работает на **бесплатных тарифах**: GitHub Free, Vercel Hobby, Neon Free. Банковская карта и свой домен не нужны —
сайт открывается по адресу `https://<имя-проекта>.vercel.app` (HTTPS включён автоматически).

## Возможности

- **Вход по паролю.** Весь сайт закрыт, открыта только страница `/login`. Пароль хранится только как bcrypt-хеш в
  переменной `APP_PASSWORD_HASH`. Сессия — защищённая cookie на 30 дней, не более 5 попыток входа в минуту с одного IP.
  Заголовки безопасности: HSTS, CSP, X-Frame-Options, Referrer-Policy.
- **Главная** — плашки форумов: даты, прогресс, счётчики «Не начато / В работе / Выполнено / Просрочено», дни до
  форума. Создание форума со стандартным списком задач (мастер-план), без задач, с задачами другого форума или из Excel. Редактирование,
  дублирование, архив, удаление.
- **База данных** — справочники: ответственные, этапы (с цветом), блоки, роли, типовой мастер-план, форумы.
  Используемые значения нельзя удалить — только архивировать.
- **Этапы и задачи** — таблица по этапам с редактированием прямо в ячейках (статус, ответственные, даты, текст по
  двойному клику), массовые действия, перетаскивание строк, вид «По статусам» (канбан), карточка задачи с историей.
- **Диаграмма Ганта** — дерево Этап → Блок → Задача, масштаб дни/недели/месяцы, линии «Сегодня», «Старт продаж»,
  «Дата форума», перетаскивание и растягивание полос с отменой (Ctrl+Z).
- **Фильтры** (общие для Ганта и списка, сохраняются в адресе страницы): этап, блок, роль, ответственный, статус,
  срок («Просрочено», «На этой неделе», «В ближайшие 14 дней», «Без даты», диапазон), поиск с подсветкой.
- **Импорт и экспорт Excel** с окном предпросмотра; выгруженный файл загружается обратно без потерь.
- **Отчёт** — кольцевые диаграммы «Расходы», «Доходы», «Кто пригласил» (красная, зелёная, синяя гаммы), редактирование
  на сайте, выгрузка в PPTX (нативные редактируемые диаграммы PowerPoint) и PDF 16:9.
- **Напоминания** — колокольчик на сайте и ежедневные письма-дайджесты ответственным, еженедельная сводка руководителю.
  Цифра у колокольчика — только новые уведомления: открыли список — они считаются просмотренными (отметка хранится в
  браузере, у каждого пользователя своя).
- **Выход после обновления сайта.** Когда выкатывается новая версия кода (новый коммит), у всех открытых вкладок
  появляется предупреждение «На сайт были внесены изменения, через 5 секунд вы будете перенаправлены на страницу
  входа», сессия завершается, и нужно войти заново. Изменения данных (задачи, отчёты) и переменных окружения выход не
  вызывают. Вкладки проверяют версию раз в минуту и при возврате на вкладку.

Единый цветовой код везде на сайте и в выгрузках:

| Цвет       | Значение                                                                                      |
| ---------- | --------------------------------------------------------------------------------------------- |
| серый      | не начато                                                                                     |
| синий      | в работе                                                                                      |
| зелёный    | выполнено / по плану                                                                          |
| красный    | просрочено / отклонение (в т. ч. «пора начинать» — дата начала наступила, а задача не начата) |
| жёлтый     | уточнить (нераспознанный срок, замечания при импорте)                                         |
| фиолетовый | старт продаж (линия на диаграмме Ганта)                                                       |

При выполнении позже срока рядом со статусом — пометка «с опозданием N дн.». У просроченных задач строка подсвечивается, в столбце «Отставание» — «+N дн.».

## Первое подключение Vercel (пошагово)

Инструкция для человека без опыта. Понадобится только аккаунт GitHub, где лежит этот репозиторий.

1. **Регистрация.** Откройте [vercel.com](https://vercel.com) → **Sign Up** → **Continue with GitHub**. Выберите
   бесплатный тариф **Hobby**. Банковская карта не нужна.
2. **Импорт репозитория.** **Add New… → Project** → найдите репозиторий в списке → **Import**. Если репозитория нет в
   списке — нажмите **Adjust GitHub App Permissions** и дайте Vercel доступ к нему.
3. **Первая сборка.** Framework определится как Next.js автоматически, ничего менять не нужно. Нажмите **Deploy**.
   Первая сборка может упасть из-за отсутствия базы данных — это нормально, продолжайте.
4. **База данных.** В проекте Vercel → вкладка **Storage** → **Create Database** → **Neon** (Postgres) → тариф
   **Free** → регион **Frankfurt (eu-central-1)** (ближе к Москве и к серверу сайта) → **Connect to project**.
   Переменные `DATABASE_URL` и `DATABASE_URL_UNPOOLED` добавятся сами.
5. **Секреты.** На своём компьютере в папке проекта выполните (нужен установленный [Node.js](https://nodejs.org) 20+):

   ```bash
   npm install
   npm run gen-secrets -- "придумайте-пароль-для-входа"
   ```

   Команда выведет готовые значения `APP_PASSWORD_HASH`, `SESSION_SECRET`, `CRON_SECRET`. В Vercel откройте
   **Settings → Environment Variables** и добавьте их по одной (Name — имя, Value — значение, окружения —
   Production, Preview, Development). Добавьте также `APP_URL` = `https://<имя-проекта>.vercel.app`.
   Если нужны письма — добавьте SMTP-переменные (см. [Напоминания по e-mail](#напоминания-по-e-mail)).

   > Без Node.js на компьютере: значения можно получить в любом онлайн-генераторе bcrypt (cost 12) для
   > `APP_PASSWORD_HASH` и любой случайной строкой длиной 40+ символов для `SESSION_SECRET` и `CRON_SECRET`.

6. **Пересборка.** **Deployments** → у последней сборки меню **⋯** → **Redeploy**. Команда сборки
   `prisma generate && prisma migrate deploy && next build` из `package.json` сама создаст таблицы в базе.
7. **Стартовые данные** (один раз). Откройте сайт, войдите по паролю, перейдите в **База данных** и нажмите
   **«Загрузить начальные данные»**. Загрузятся справочники, 149 задач типового мастер-плана и демо-форум
   «СтройТех’26» с отчётом. Альтернатива — локально: `npm run db:seed` с `DATABASE_URL` из Vercel.
8. **Готово.** Откройте `https://<имя-проекта>.vercel.app` и войдите. Каждый push в ветку `main` обновляет сайт
   автоматически, а для каждого Pull Request Vercel создаёт отдельный preview-адрес.
9. **Напоминания.** Файл `vercel.json` уже содержит одно cron-задание в сутки (`0 6 * * *` — 09:00 МСК). Vercel
   подключит его сам; на тарифе Hobby запуск происходит в пределах указанного часа.

## Переменные окружения

Пример — в файле [`.env.example`](.env.example).

| Переменная                                             | Обязательна | Описание                                                                                       |
| ------------------------------------------------------ | ----------- | ---------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                                         | да          | Строка подключения Neon Postgres (Vercel подставляет сам)                                      |
| `DATABASE_URL_UNPOOLED`                                | да          | Прямое подключение для миграций (Vercel подставляет сам; локально — то же, что `DATABASE_URL`) |
| `APP_PASSWORD_HASH`                                    | да          | bcrypt-хеш пароля входа (`npm run hash-password`)                                              |
| `SESSION_SECRET`                                       | да          | Случайная строка ≥ 32 символов                                                                 |
| `CRON_SECRET`                                          | да          | Секрет для `/api/cron/*` (Vercel передаёт его в заголовке автоматически)                       |
| `APP_URL`                                              | желательно  | `https://<имя-проекта>.vercel.app` — для ссылок в письмах                                      |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD` | нет         | Почта для напоминаний. Без них напоминания работают только на сайте                            |

> В локальном файле `.env` знаки `$` в хеше пароля нужно экранировать: `\$2b\$12\$…` —
> команды `gen-secrets` и `hash-password` выводят обе версии. В Vercel значение вставляется как есть.

## Локальный запуск

```bash
npm install
cp .env.example .env            # заполните значения (см. ниже)
docker compose up -d            # локальный Postgres (или используйте отдельную ветку БД в Neon)
npx prisma migrate deploy       # создать таблицы
npm run db:seed                 # справочники, мастер-план и демо-форум
npm run dev                     # http://localhost:3000
```

Для локального Postgres из `docker-compose.yml`:

```
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/forums
DATABASE_URL_UNPOOLED=postgresql://postgres:postgres@localhost:5432/forums
```

Для Neon создайте в консоли Neon отдельную ветку (**Branches → New branch**, например `dev`) и возьмите её строку
подключения, чтобы не трогать рабочие данные.

## Как сменить пароль

1. Выполните `npm run hash-password -- "новый-пароль"` и скопируйте значение `APP_PASSWORD_HASH`.
2. Vercel → **Settings → Environment Variables** → `APP_PASSWORD_HASH` → **Edit** → вставьте новое значение → **Save**.
3. **Deployments → Redeploy.** Старый пароль перестанет работать.
4. Чтобы разлогинить всех, у кого открыт сайт, замените также `SESSION_SECRET` (например, на новое значение из
   `npm run gen-secrets`) и сделайте Redeploy.

## Резервная копия базы данных

Все данные (включая отчёты) хранятся в Neon Postgres, файлы на Vercel не сохраняются.

- **Выгрузка планов в Excel.** Кнопка «Выгрузить план» на странице форума — простая копия плана, которую можно
  загрузить обратно.
- **Полная копия БД** (рекомендуется раз в неделю). Установите PostgreSQL client (`pg_dump`) и выполните, подставив
  строку `DATABASE_URL_UNPOOLED` из Vercel (Settings → Environment Variables → показать значение):

  ```bash
  pg_dump "postgresql://…neon.tech/neondb?sslmode=require" --no-owner --format=custom -f backup-$(date +%F).dump
  ```

  Восстановление в пустую базу:

  ```bash
  pg_restore --no-owner --clean --if-exists -d "postgresql://…/neondb?sslmode=require" backup-2026-09-23.dump
  ```

- **Ветки Neon.** В консоли Neon (**Branches → New branch**) можно сделать мгновенную копию базы перед рискованными
  изменениями. Neon Free также хранит короткую историю изменений (restore по времени в пределах окна, доступного на
  бесплатном тарифе).

## Напоминания по e-mail

Письма отправляются через **обычный почтовый ящик по SMTP** — бесплатно, без своего домена.

Яндекс Почта:

1. [id.yandex.ru](https://id.yandex.ru) → **Безопасность → Пароли приложений** → создайте пароль для «Почта».
2. В настройках почты (**Все настройки → Почтовые программы**) включите доступ по IMAP/SMTP.
3. Переменные: `SMTP_HOST=smtp.yandex.ru`, `SMTP_PORT=465`, `SMTP_USER=ваш@yandex.ru`, `SMTP_PASSWORD=пароль приложения`.

Mail.ru: `SMTP_HOST=smtp.mail.ru`, `SMTP_PORT=465`, пароль приложения создаётся в **Настройки → Безопасность →
Пароли для внешних приложений**.

Как работает:

- Ежедневно около 09:00 МСК каждому ответственному (активному, с e-mail) уходит **одно** письмо со списком его задач
  по всем активным форумам: срок через N дней (по умолчанию 3), просрочено, «пора начинать» (дата начала наступила,
  а статус «Не начато»).
- По понедельникам руководителю (адреса — на странице «Напоминания») уходит сводка по каждому форуму: выполнено,
  в работе, просрочено и топ-10 просрочек.
- Повторные письма об одной задаче в тот же день не отправляются; число писем за запуск ограничено настройкой
  (по умолчанию 50) — с учётом суточных лимитов бесплатной почты.
- Все отправки записываются в журнал на странице «Напоминания». Там же — кнопка ручного запуска для проверки.
- Без SMTP напоминания видны только на сайте (колокольчик в шапке), сборка и работа сайта не нарушаются.

## Формат Excel и правила сроков

Лист «Мастер-план форума», столбцы:
`№ | Этап | Блок / направление | Описание задачи | Срок готовности (относительно даты форума) | Ответственный блок / роль | Статус | Комментарий / примечание`.
Необязательные столбцы распознаются: `Ответственный (ФИО)`, `Дата начала`, `Дата окончания`, `Дата выполнения`.
Роли вида «Ивент / Маркетинг» разбиваются по `/`. Новые этапы, блоки, роли и сотрудники добавляются в справочники
после подтверждения в окне предпросмотра. Образец — [`seed/master-plan.xlsx`](seed/master-plan.xlsx).

Перевод текста срока в даты (`F` — начало форума, `FE` — окончание, `S` — старт продаж):

| Текст срока                                                                             | Окончание                           | Начало                                |
| --------------------------------------------------------------------------------------- | ----------------------------------- | ------------------------------------- |
| «за N дней / недель / месяцев до форума»                                                | F − N                               | окончание − 7 дней                    |
| «за N–M недель до форума»                                                               | F − N (меньшее)                     | F − M (большее)                       |
| «за 1 день до форума, к 18:00» и другие уточнения (после запятой, в скобках, после «;») | по числу; уточнение → в комментарий | окончание − 1 день                    |
| «контрольная точка, за 4 месяца»                                                        | F − 4 месяца (веха)                 | = окончанию                           |
| «до старта продаж»                                                                      | S                                   | S − 60 дней                           |
| «с начала продаж», «…, далее на регулярной основе»                                      | F − 1                               | S                                     |
| «в дни форума» / «в день монтажа», «период монтажа»                                     | FE / F − 1                          | F / F − 1                             |
| «в день окончания форума / на следующий день»                                           | FE + 1                              | FE                                    |
| «на следующий день после форума»                                                        | FE + 1                              | FE + 1                                |
| «в течение N дней после форума»                                                         | FE + N                              | FE + 1                                |
| «в течение N рабочих дней после форума»                                                 | FE + N рабочих дней                 | FE + 1                                |
| «на протяжении этапа, не позднее N недель до форума»                                    | F − N недель                        | начало этапа                          |
| «на протяжении этапа…», «по графику платежей договоров», «при выборе площадки» и прочее | конец этапа                         | начало этапа, пометка «уточнить срок» |

Границы этапов: 1 — от S − 60 до S; 2 — от S до F − 1; 3 — от F до FE; 4 — от FE + 1 до FE + 30.
Если у форума меняются даты, приложение предлагает пересчитать даты задач, которые не редактировались вручную.
Парсер — `src/lib/term-parser.ts`, тесты на все варианты сроков мастер-плана — `tests/unit/term-parser.test.ts`.

## Тесты и проверки

```bash
npm test                  # unit-тесты: парсер сроков, статусы и отставание, фильтры, Excel, отчёт
npm run test:e2e          # вход → создание форума → импорт Excel → смена статуса → экспорт PPTX
npm run lint && npm run typecheck && npm run format:check
```

E2E-тест запускает `npm run dev` (или использует уже запущенный сервер) и нужную БД из `.env`. Пароль для входа
передаётся в `E2E_PASSWORD` (по умолчанию `forum2026`). Адрес другого стенда — `E2E_BASE_URL`.

## Ограничения бесплатных тарифов

- **Vercel Hobby:** одно cron-задание в сутки; ограниченное время работы функций — поэтому импорт Excel и экспорт
  PPTX/PDF выполняются в браузере, а на сервер передаются только данные.
- **Neon Free:** база «засыпает» при простое, первый запрос после паузы идёт на несколько секунд дольше — сайт
  показывает индикатор загрузки. Объём небольшой (сотни МБ), для текстовых данных этого хватает с запасом; картинки и
  файлы в БД не хранятся.
- Платные сервисы мониторинга, аналитики, почты и хранилищ не используются.

## Структура проекта

```
prisma/               схема БД, миграции, seed-скрипт
seed/                 мастер-план (Excel), черновик отчёта (PDF), исходное ТЗ
scripts/              hash-password, gen-secrets
src/app/              страницы (App Router) и API: /login, /, /database, /settings, /forums/[id]/{gantt,tasks,report}
src/components/       интерфейс: ui/ (базовые компоненты), forum/ (Гант, таблица, фильтры), report/, database/
src/lib/              логика без привязки к серверу: даты, парсер сроков, статусы, фильтры, Excel, отчёт (PPTX/PDF)
src/server/           запросы к БД, server actions, напоминания, seed
src/middleware.ts     проверка сессии для всех страниц и API
```
